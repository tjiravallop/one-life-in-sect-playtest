4. แบบจำลองสถานที่
4.1 แบ่งเป็นพื้นที่และจุดภายในพื้นที่
พื้นที่หลัก ใช้กับการเดินทางและเหตุการณ์ระดับโลก เช่น เมืองตลาด เขตสำนัก หมู่บ้าน หรือเขตป่า

จุดภายในพื้นที่ ใช้กับบริการและกิจกรรม เช่น ร้านตำรา โรงเตี๊ยม ลานฝึก หรือหอคัมภีร์

ตัวอย่าง:
เมืองตลาดชายแดน
├─ ตลาดวัตถุดิบ
├─ ร้านตำรา
├─ โรงเตี๊ยม
└─ จุดรับงาน

เขตสำนักเมฆาคราม
├─ ลานฝึก
├─ หอคัมภีร์ชั้นต้น
├─ ที่พักศิษย์
└─ จุดรับงานสำนัก
การเดินทาง ข้ามพื้นที่หลัก ใช้เวลาและทรัพยากร ส่วนการเปิดจุดบริการ ในพื้นที่เดียวกัน ไม่เสียเดือนเพิ่ม เว้นแต่กิจกรรมที่ทำในจุดนั้นมีกติกาใช้เวลาอยู่แล้ว

4.3 ID กลาง
ทุกพื้นที่ จุดบริการ เส้นทาง และพื้นที่สำรวจต้องมี ID ที่ไม่ซ้ำและคงที่ เช่น border_market โดย:
- ชื่อที่ผู้เล่นเห็นแก้ได้โดยไม่ทำให้เซฟพัง
- ร้าน เส้นทาง เหตุการณ์ และ NPC อ้างด้วย ID
- มีตัวตรวจว่าทุก ID ที่อ้างถึงมีอยู่จริง
- มีตารางจับคู่ ID เก่ากับ ID ใหม่สำหรับเซฟเดิม

นี่เป็นเพียงโครงสร้างเสนอ ชื่อฟิลด์จริงต้องเลือกหลังตรวจการใช้งาน locations และ travel เดิมทั้งหมด เพื่อไม่ให้มีข้อมูลตำแหน่งสองชุดที่เปลี่ยนแยกกัน
ความหมายที่ต้องแยก
- รู้จักพื้นที่: รู้ว่ามีสถานที่นี้
- ไปถึงได้: มีเส้นทางและผ่านเงื่อนไขเดินทาง
- อยู่ในพื้นที่: ตำแหน่งปัจจุบันของตัวละคร
- มีสิทธิ์ใช้บริการ: เช่น เป็นศิษย์หรือได้รับอนุญาต
- มีกรรมสิทธิ์: เช่น บ้านของตนเอง
- สถานที่เปิดอยู่: ไม่ถูกทำลาย ปิดล้อม หรือปิดชั่วคราว
การรู้จักสำนักไม่ได้หมายความว่าเข้าใช้หอคัมภีร์ได้ และการมีบ้านไม่ได้หมายความว่าเข้าถึงบ้านจากทุกเมืองได้ทันที
6. กติกาการเปลี่ยนสถานที่
1. ตัวละครอยู่ในพื้นที่หลักเพียงแห่งเดียว หรืออยู่ระหว่างเดินทาง
2. การเปลี่ยนกิจกรรมไม่ย้ายข้ามพื้นที่โดยอัตโนมัติ
3. การเลือกจุดบริการในพื้นที่เดียวกันไม่เปลี่ยนพื้นที่หลัก
4. เมื่อเดินทางสำเร็จ เปลี่ยนตำแหน่งเป็นปลายทางและคงอยู่จนออกเดินทางอีกครั้ง
5. หากกำลังเดินทาง ต้องไม่เปิดร้านหรือกิจกรรมที่ต้องอยู่ในเมือง
6. หากเดินทางถูกขัดขวาง เกมต้องมีสถานะและข้อความอธิบายว่าตัวละครอยู่ที่ใด
7. หากสถานที่ถูกปิดหรือทำลาย ต้องมีทางออกที่เล่นต่อได้ ไม่ขังตัวละครในสถานะใช้งานไม่ได้
การฝึกหรือพักอาจทำได้หลายพื้นที่ แต่ใช้ผลตามสภาพแวดล้อม เช่น ความปลอดภัยหรืออัตราฟื้นฟู ไม่จำเป็นต้องบังคับกลับสำนักทุกครั้ง
7. ระบบเส้นทางและการเดินทาง
7.1 ข้อมูลเส้นทาง
แต่ละเส้นทางควรระบุ:
- ต้นทางและปลายทาง
- เดินทางย้อนกลับได้หรือไม่
- เวลา เงิน เสบียง สุขภาพ และความเสี่ยงพื้นฐาน
- เงื่อนไขเปิด เช่น รู้เส้นทาง มีแผนที่ หรือผ่านช่วงเนื้อเรื่อง
- สถานะปิดจากเหตุการณ์โลก
- ประเภทเหตุการณ์ระหว่างทางที่รองรับ
หากเส้นทางไป–กลับมีต้นทุนต่างกัน ควรกำหนดแยกอย่างชัดเจน ไม่สมมติว่าเท่ากันทุกเส้น
7.2 หน้าก่อนเดินทาง
แสดง:
- ต้นทาง → ปลายทาง
- เวลาและวันถึงโดยประมาณ
- ค่าใช้จ่ายและเสบียงรายเดือนกับยอดรวม
- สุขภาพและอายุขัยที่อาจเสีย
- ความปลอดภัยและคำอธิบายความเสี่ยง
- ค่าที่ตัวละครมีเทียบกับที่ต้องใช้
- เหตุผลเมื่อยังออกเดินทางไม่ได้
ราคาจริงของเส้นทางให้ยึดข้อมูลเดิมเป็นจุดเริ่มต้น แล้วทดสอบสมดุลก่อนปรับ
7.3 ระหว่างเดินทางและเมื่อถูกขัดขวาง
- แสดงเวลาที่เหลือและทรัพยากรที่ยังต้องใช้
- เก็บสถานะเมื่อบันทึกหรือโหลด
- หากเงินหรือเสบียงหมด ให้หยุดในสถานะระหว่างทาง พร้อมทางเลือกที่ออกแบบรองรับ
- ห้ามให้ผล “ถึงปลายทาง” หรือเปิดร้านปลายทางก่อนเดินทางสำเร็จ
- หากเหตุการณ์ทำให้ล่าช้า ต้องปรับยอดที่ยังต้องใช้ให้ตรงกับการเดินเวลาจริง
7.4 เมื่อเดินทางถึง
- ตั้งพื้นที่ปัจจุบันเป็นปลายทาง
- แจ้งจุดบริการและกิจกรรมที่ใช้ได้
- คงตำแหน่งหลังเวลาผ่านไปและหลังโหลดเซฟ
- คำนวณเส้นทางครั้งต่อไปจากตำแหน่งใหม่
8. กิจกรรมและสิทธิ์ตามสถานที่

→ ตรวจพื้นที่และบริการ

→ แจ้งว่าทำได้หรือบอกเหตุผล

งานสำนัก	ต้องอยู่บริเวณและมีสิทธิ์ที่เหมาะสม
ซื้อขาย	ต้องอยู่ในพื้นที่และใช้บริการร้านที่เปิดอยู่


หากยังทำไม่ได้ หน้าจอควรบอก เหตุผล ค่าปัจจุบัน และขั้นต่อไป เช่น “ต้องเป็นศิษย์ใน ปัจจุบันเป็นศิษย์นอก” พร้อมบอกว่าดูเงื่อนไขเลื่อนขั้นได้ที่ไหน
9. ร้านค้า
9.1 ร้านวัตถุดิบ
ย้ายการเข้าถึงจากท้ายแท็บสร้างของไปเป็น บริการร้านค้าในเมือง โดยยังคงสินค้าและกติกาเดิมเป็นจุดเริ่มต้น:
- ซื้อวัตถุดิบสามัญและชั้นดี
- ขายวัตถุดิบและไอเทมที่ขายได้
- แสดงจำนวนเงิน จำนวนของ และราคาต่อชิ้น
- แสดงเหตุผลเมื่อซื้อหรือขายไม่ได้
- ซื้อขายได้ตราบเท่าที่อยู่ในพื้นที่และร้านเปิด
การซื้อขายไม่จำเป็นต้องเสียเวลาเป็นเดือนในระยะแรก เพราะระบบเดิมทำทันที แต่ต้องทดสอบว่าการซื้อขายซ้ำสร้างกำไรผิดปกติหรือไม่
9.2 ร้านตำรา
เพิ่มร้านตำราพื้นฐานหลังระบบพื้นที่ทำงานมั่นคง:
- เริ่มจากคัมภีร์พื้นฐานจำนวนน้อยที่เหมาะกับตลาดทั่วไป
- แสดง ประเภท ขั้นขั้นต่ำ เพดานวิชา ราคา และสถานะว่าเรียนได้หรือยัง
- ซื้อแล้วเข้าคลัง และต้องเรียนกับติดตั้งตามระบบเดิม
- หลีกเลี่ยงการมีคัมภีร์ระดับสูงทุกเล่มขายในตลาดทั่วไป
- ก่อนขายคัมภีร์ ต้องตรวจความสำคัญต่อเนื้อเรื่องหรือทางเดินของผู้เล่น
สิ่งที่ยังต้องกำหนดผ่านการทดสอบ: ราคาคัมภีร์ จำนวนเงินที่ผู้เล่นหาได้ตามวัย และขอบเขตสินค้าที่ร้านเติมกลับมา ตัวเลขเหล่านี้ไม่ควรล็อกก่อนทดลองเล่นจริง
10. การสำรวจ
ย้ายข้อมูลพื้นที่สำรวจไป data/exploration-areas.js แล้วระบุว่าแต่ละพื้นที่เชื่อมกับพื้นที่หลักใด

ผู้เล่นควรเห็น:
- ชื่อพื้นที่และวิธีเข้าถึง
- ความเสี่ยงและความพร้อมของตัวละคร
- สิ่งที่อาจพบในภาพรวม
- เวลาและทรัพยากรที่ต้องใช้
- เมื่อสำรวจจบ ตัวละครกลับมาจุดเดิมหรือย้ายไปที่ใหม่
ต้องแยกผลให้ชัดว่า รู้ว่ามีพื้นที่, เดินทางถึง, สำรวจสำเร็จ, และ ได้เบาะแส เป็นคนละสถานะ โดยเฉพาะกรณีที่ทดสอบแล้วพบว่า “หลงทาง” แต่ยังตั้งค่าเบาะแสสำเร็จ
11. เนื้อเรื่องหลินอัน
ก่อนบังคับเงื่อนไข Location ต้องทำรายการเหตุการณ์เนื้อเรื่องและจัดประเภท:
ประเภท	ตัวอย่างแนวทาง
เกิดได้หลายพื้นที่	ข่าวลือหรือเหตุการณ์ที่เดินทางมาหาตัวละครได้
ต้องอยู่พื้นที่เฉพาะ	ฉากในหอคัมภีร์หรือการประชุมสำนัก
เรื่องพาตัวละครย้าย	ถูกพาหนี เดินทางกับคาราวาน หรือเข้าสำนัก
มีเส้นตาย	ศึกหรือเหตุการณ์ที่เกิดตามเวลาโลก


สำหรับแต่ละฉากต้องกำหนดว่า ถ้าตัวละครอยู่นอกพื้นที่หรือกำลังเดินทางจะเกิดอะไรขึ้น เช่น เลื่อนฉาก มีข่าวแจ้ง หรือมีเส้นทางผลลัพธ์เมื่อไปไม่ทัน

ระยะแรกให้รักษาเส้นทางเนื้อเรื่องเดิมก่อน อย่าเปิดกฎพื้นที่เข้มทั่วทั้งเรื่องจนฉากสำคัญขาดหรือผู้เล่นติดทางตัน ฉากที่เรื่องจำเป็นต้องพาไปที่อื่นต้องอธิบายการย้ายให้ผู้เล่นเห็น
12. การรองรับ NPC ในอนาคต
Location ควรเตรียมให้ NPC อ้างพื้นที่เดียวกับผู้เล่น แต่ยังไม่บังคับว่าทุกร้านต้องมี NPC จำลองชีวิตจริงทันที

เมื่อระบบ NPC พร้อม จึงเพิ่ม:
- ตำแหน่งและสถานะของ NPC แต่ละคน
- การตรวจว่าอยู่พื้นที่เดียวกัน มีชีวิต และพร้อมพบ
- ความสัมพันธ์และความทรงจำที่ผูกกับ ID ของคนจริง
- ผู้สอนรู้วิชาอะไร และมีเหตุผลใดจึงยอมสอน
- การย้ายถิ่น ออกจากพื้นที่ หรือเสียชีวิตโดยไม่กลับมาโผล่ผิดบริบท
ผู้เล่นจึงจะตามหาอาจารย์หรือผู้พเนจรคนเดิมได้อย่างมีเหตุผล ไม่ใช่เพิ่มคะแนน “อาจารย์” แล้วมีคนสอนขึ้นมาโดยไม่มีที่มา
13. แปลงเซฟเก่า
ต้องทำตัวแปลงเซฟที่ตรวจซ้ำได้และไม่เปลี่ยนข้อมูลทุกครั้งที่โหลด:
1. สำรองข้อมูลเซฟก่อนแปลง
2. ตรวจเวอร์ชันและสร้างฟิลด์ใหม่เฉพาะเมื่อยังไม่มี
3. จับคู่สถานที่เดิมกับพื้นที่ใหม่ตามข้อมูลที่เชื่อถือได้
4. รักษาการเดินทางที่ค้างอยู่ เวลา ค่าใช้จ่าย และเหตุการณ์ที่รอเลือก
5. รักษาสิ่งของ เงิน อายุ ความสัมพันธ์ และความคืบหน้าเนื้อเรื่อง
6. หากตำแหน่งเดิมกำกวมหรือข้อมูลขัดกัน ใช้ตำแหน่งเริ่มต้นที่เหมาะกับโหมดและแจ้งผู้เล่น
7. โหลดเซฟที่แปลงแล้วซ้ำเพื่อตรวจว่าไม่ย้ายพื้นที่ เพิ่มของ หรือหักเงินซ้ำ
ไม่ควรตีความว่าเคยถึงตลาดในอดีตแล้วแปลว่าปัจจุบันยังอยู่ตลาดเสมอ เพราะ lastArrival เป็นประวัติการมาถึง ไม่ใช่หลักฐานตำแหน่งปัจจุบันทุกกรณี
14. ขั้นตอนลงมือพัฒนา
ระยะ A — สำรวจและวางตารางจับคู่
- รวบรวมการอ่านและเขียนตำแหน่งทั้งหมดใน app.js
- ทำตารางจับคู่สถานที่พัก ปลายทาง และพื้นที่สำรวจเดิม
- สำรวจเหตุการณ์ที่ย้ายตัวละครหรืออ้างสถานที่
- ระบุกรณีเซฟเก่าและเส้นทางที่ยังไม่มีคู่ในข้อมูลใหม่
เกณฑ์ผ่าน: รู้ว่าระบบใดพึ่งตำแหน่งเดิม และไม่มีปลายทางเดิมตกหล่น
ระยะ B — แยกไฟล์ข้อมูลโดยรักษาพฤติกรรมเดิม
- ย้ายข้อมูลไป data/locations.js, travel-routes.js, exploration-areas.js และ shops.js ตามความเหมาะสม
- เพิ่มลำดับโหลดใน index.html
- ให้ app.js ใช้ข้อมูลจากไฟล์ใหม่
- เพิ่มตัวตรวจ ID และข้อมูลอ้างอิง
- ตรวจว่าเริ่มเกม เดินทาง พัก และซื้อขายได้เท่าเดิมก่อนเปลี่ยนกติกา
เกณฑ์ผ่าน: ไม่มีข้อมูลหาย ไม่มีข้อผิดพลาดจากการโหลด และพฤติกรรมเดิมที่ต้องรักษายังทำงาน
ระยะ C — ตำแหน่งและเดินทางชุดใหม่
- เพิ่มพื้นที่ปัจจุบันและสถานะระหว่างทาง
- เชื่อมเส้นทางต้นทาง–ปลายทาง
- แก้เดินทางถึงแล้วคงตำแหน่ง
- เพิ่มการแปลงเซฟและรองรับเดินทางล้มเหลว
- ป้องกันการเปลี่ยนกิจกรรมแล้วย้ายพื้นที่โดยไม่ตั้งใจ
เกณฑ์ผ่าน: ไปตลาด รอหลายเดือน โหลดเซฟ และยังอยู่ตลาดจนเดินทางออก
ระยะ D — จุดบริการและร้านค้า
- เพิ่มหน้าสถานที่และจุดบริการ
- เชื่อมร้านวัตถุดิบเดิม
- เพิ่มร้านคัมภีร์พื้นฐาน
- แสดงเงื่อนไข ราคา และผลลัพธ์ก่อนซื้อ
เกณฑ์ผ่าน: ผู้เล่นใหม่เดินทาง ซื้อคัมภีร์ เรียน ติดตั้ง และฝึกได้โดยไม่ต้องค้นระบบจากหลายหน้าจอ
ระยะ E — กิจกรรม สำรวจ และเนื้อเรื่อง
- เชื่อมกิจกรรมและพื้นที่สำรวจกับ Location
- ไล่เหตุการณ์หลินอันและเส้นทางทางเลือก
- จัดการฉากที่ต้องอยู่เฉพาะพื้นที่หรือมีเส้นตาย
- ทดสอบไม่ให้ฉากสำคัญหายและไม่ให้ผู้เล่นติดทางตัน
ระยะ F — จุดเชื่อม NPC
- เตรียมพื้นที่และจุดที่ NPC อ้างได้
- เชื่อมตัวละครเนื้อเรื่องที่มีอยู่ก่อน
- ออกแบบ NPC ทั่วไปเป็นงานถัดไปตามแนวทางในเอกสาร NPC

หลินอัน	เล่นทั้งเส้นทางเข้าสำนักและไม่เข้าสำนักจนถึงบทสรุป
โหมดอิสระ	เล่นหลายแนว ตั้งแต่เกิดจนมีโอกาสเริ่มบำเพ็ญ รวมถึงคนที่ไม่เข้าสำนัก

มือถือ	มองเห็นสถานที่ ร้าน และเหตุผลที่กดไม่ได้โดยไม่ต้องค้นหลายหน้า
